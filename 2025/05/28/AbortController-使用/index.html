AbortController 终止异步请求

Created2025-05-28|Updated2025-10-14
|Post Views:

背景

在 Web 开发中，处理异步请求（常见于 fetch 等 io 操作）时，通常需要在修改状态（如即时检索的场景）、销毁组件（如退出页面的场景），终止当前不再需要的请求，以节省当前机器的资源消耗，达到性能优化的目的。而 Web 环境下的 JavaScript 则提供了 AbortController 的原生接口，为解决这一问题提供了优雅的方案。本文将介绍它的核心用法、适用场景及示例代码。

什么是 AbortController？

AbortController 是一个用于中止一个或多个 Web 请求的 web API。它通过 AbortSignal 对象与异步操作（如 fetch）进行通信，从而是开发者能够在需要时主动终止请求。

最常见的场景就是数据请求的竞态处理中，稍后本文会给出相应的例子介绍。

核心概念

  • AbortController.abort(): 触发中止操作。

  • AbortController.signal: 传递给异步任务的信号对象，用于异步请求监听中止事件。

注意事项

  1. 重复调用 abort() 不会报错，只有第一次生效。

  2. 如果请求已完成（成功或失败），调用 abort() 不会有任何效果。

  3. 一旦将 signal 传递给异步任务，其生命周期由该任务管理，避免内存泄漏。

总结

AbortController 为管理异步任务提供了强大的控制能力，尤其在处理复杂交互和性能优化时至关重要。合理使用可以显著提升应用的健壮性和用户体验。可以在涉及 fetch、WebSocket 或 setTimeout 等异步场景中大胆尝试。
